## 1.1 ที่มาและเหตุผล
ข้อมูลคำสั่งซื้อ (Order) มักถูกส่งต่อระหว่างระบบหรือทีมงานในรูปแบบไฟล์ CSV ซึ่งเกิดปัญหาคุณภาพข้อมูลได้ง่าย เช่น

1) ค่าที่ขาดหาย เช่น ไม่มีรหัสคำสั่งซื้อ
2) ข้อมูลซ้ำ เช่น `order_id` ซ้ำกัน
3) รูปแบบไม่ถูกต้อง เช่น วันที่อ่านไม่ได้ หรือจำนวนเงินติดลบ/ไม่ใช่ตัวเลข
4) ตรวจสอบด้วยมือได้ช้าและพลาดง่าย โดยเฉพาะไฟล์ขนาดใหญ่ และไม่มีประวัติให้ติดตามแนวโน้มคุณภาพ

ผู้พัฒนาจึงพัฒนาระบบ Order CSV Quality Monitor เพื่อตรวจสอบไฟล์ CSV อัตโนมัติ รายงานแถวที่มีปัญหา และเก็บประวัติการตรวจสอบ

## 1.2 วัตถุประสงค์
1) เพื่อพัฒนาระบบตรวจสอบคุณภาพไฟล์ CSV คำสั่งซื้อตามกฎที่กำหนด
2) เพื่อรองรับ CSV ทั่วไปด้วยการสร้างกฎอัตโนมัติจากเนื้อหาไฟล์
3) เพื่อจัดเก็บประวัติการตรวจสอบและแสดงแนวโน้ม Pass Rate
4) เพื่อวัดความแม่นยำของกฎด้วย Precision / Recall / F1

## 1.3 ขอบเขตของโครงงาน
### 1.3.1 ขอบเขตด้านฟังก์ชัน
- อัปโหลดและตรวจสอบไฟล์ CSV
- กฎสำหรับไฟล์ Order: missing_id, duplicate_id, invalid_date, invalid_amount
- โปรไฟล์คอลัมน์และกฎอัตโนมัติสำหรับ CSV ทั่วไป
- ตัดสินผล PASS / WARN / FAIL ตามเกณฑ์
- ดาวน์โหลดรายงานแถวที่มีปัญหา
- ประวัติการตรวจสอบและกราฟแนวโน้ม
- การประเมินความแม่นยำด้วยชุดข้อมูลที่มีเฉลย

### 1.3.2 ขอบเขตด้านเทคโนโลยี
- Frontend: Streamlit
- Backend: Python, pandas, PyYAML
- Database: SQLite
- Testing / CI: pytest, GitHub Actions
- Deployment: Streamlit Community Cloud

### 1.3.3 ขอบเขตด้านผู้ใช้
Data Analyst, Data Owner, Data Steward และ Developer (รายละเอียดใน [use_cases.md](./use_cases.md))

### 1.3.4 นอกขอบเขต
การดึงข้อมูลจากแหล่งต้นทางอัตโนมัติ, การแก้ข้อมูลที่ระบบต้นทาง และการตรวจสอบตามกำหนดเวลา

## 1.4 ประโยชน์ที่ได้รับ
1) ลดเวลาและความผิดพลาดในการตรวจสอบไฟล์ด้วยมือ
2) ผู้ส่งข้อมูลได้รายงานที่ระบุเลขแถวและกฎที่ไม่ผ่าน
3) ปรับกฎได้ผ่าน YAML โดยไม่ต้องแก้โค้ด
4) ติดตามแนวโน้มคุณภาพข้อมูลย้อนหลังได้
