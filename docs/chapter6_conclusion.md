# บทที่ 6
# สรุปผลและข้อเสนอแนะ

## 6.1 สรุปผลการดำเนินงาน
ระบบ Order CSV Quality Monitor ตรวจสอบไฟล์ CSV คำสั่งซื้อได้ตามกฎที่กำหนด รองรับ CSV ทั่วไปด้วยกฎที่สร้างอัตโนมัติ ตัดสินผล PASS / WARN / FAIL เก็บประวัติลง SQLite และแสดงแนวโน้มบนหน้าเว็บ ผ่านการทดสอบ 19 tests และได้ F1 = 1.000 บนชุดมาตรฐาน

## 6.2 ข้อจำกัด
1) F1 = 1.0 บนชุดมาตรฐานสะท้อนว่าโค้ดตรงกับข้อกำหนด ไม่ได้พิสูจน์ว่าข้อกำหนดครบถ้วน
2) ชุด Hard ได้ F1 = 0.5 เพราะนิยามเฉลยของแถวว่างไม่ครบ
3) ยังไม่ตรวจค่าผิดปกติ ช่วงวันที่ และรูปแบบรหัส
4) SQLite บน Streamlit Cloud ไม่ถาวร
5) ยังไม่ได้ทดสอบกับผู้ใช้จริง

## 6.3 ข้อเสนอแนะ
- ตรวจจับ anomaly ของจำนวนเงิน และช่วงวันที่
- บังคับรูปแบบ ID (เช่น `ORD-XXXX`) และรองรับรูปแบบวันที่ท้องถิ่น
- ย้ายไป PostgreSQL เพื่อเก็บประวัติถาวร
- แจ้งเตือน Slack/Discord และเปิดเป็น API (FastAPI)
- ทดสอบกับผู้ใช้และบันทึกผล
