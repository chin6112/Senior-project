# ทฤษฎีและเทคโนโลยีที่เกี่ยวข้อง

## 2.1 คุณภาพข้อมูล (Data Quality)
คุณภาพข้อมูลคือความเหมาะสมของข้อมูลต่อการนำไปใช้งาน มิติที่เกี่ยวข้องกับโครงงานนี้คือ

| มิติ | ความหมาย | กฎในระบบ |
|------|----------|----------|
| Completeness | ข้อมูลครบ ไม่ขาดหาย | `missing_id`, `not_null` |
| Uniqueness | ไม่มีข้อมูลซ้ำ | `duplicate_id`, `duplicate_row` |
| Validity | ค่าอยู่ในรูปแบบ/ช่วงที่ถูกต้อง | `invalid_date`, `invalid_amount` |

## 2.2 การตรวจสอบข้อมูลตามกฎ (Rule-based Validation)
กำหนดเงื่อนไขที่ข้อมูลต้องผ่าน แล้วรายงานแถวที่ละเมิด ข้อดีคืออธิบายผลได้ชัดเจนและปรับกฎได้ง่าย ข้อจำกัดคือจับได้เฉพาะปัญหาที่เขียนกฎไว้ล่วงหน้า ระบบนี้เก็บกฎไว้ในไฟล์ YAML เพื่อแยกกฎออกจากโค้ด

## 2.3 การทำโปรไฟล์ข้อมูล (Data Profiling)
การวิเคราะห์ลักษณะข้อมูล เช่น ชนิดของคอลัมน์ สัดส่วนค่าว่าง จำนวนค่าไม่ซ้ำ เพื่อให้ระบบสร้างกฎให้ CSV ที่ไม่รู้โครงสร้างล่วงหน้าได้ (`infer_config`)

## 2.4 ตัวชี้วัดการประเมิน
- **Precision** = TP / (TP + FP) สัดส่วนที่ระบบแจ้งแล้วเป็นปัญหาจริง
- **Recall** = TP / (TP + FN) สัดส่วนปัญหาจริงที่ระบบตรวจพบ
- **F1-Score** = 2PR / (P + R) ค่าเฉลี่ยฮาร์โมนิกของทั้งสอง
- **Macro-average** คือค่าเฉลี่ยของแต่ละกฎโดยให้น้ำหนักเท่ากัน

## 2.5 เทคโนโลยีที่ใช้
- **Python / pandas:** ประมวลผลข้อมูลตารางและตรวจสอบแบบเวกเตอร์
- **PyYAML:** อ่านไฟล์กฎ
- **Streamlit:** สร้างเว็บแอปด้วย Python โดยไม่ต้องเขียน HTML/JavaScript
- **SQLite:** ฐานข้อมูลแบบไฟล์ ไม่ต้องติดตั้งเซิร์ฟเวอร์ เหมาะกับเก็บประวัติขนาดเล็ก
- **pytest:** กรอบการทดสอบหน่วย
- **GitHub Actions:** รันการทดสอบอัตโนมัติ (CI)
